# Durable decisions

These are choices a maintainer should preserve unless the underlying product or provider constraints change materially.

1. **Keep the product browser-first and local-only.** There is no login, server-side user database, or journey-history feature. Profiles and bounded caches live in browser `localStorage` under a versioned namespace.
2. **Keep the commute model fixed.** Pendel-Pilot models one home/work profile as `homeAddress → homeStation → workStation → workAddress` and supports only `journeyWork` and `journeyHome`. A calculation may return several connection options for the same profile and direction; each option is a complete canonical journey. Multi-stop trips, fare buying, calendar automation, push alerts, and recommendation features are out of scope.
3. **Treat Transitous time as the source of truth for public transport.** `homeStationTime` and `workStationTime` are immutable anchors. If Transitous cannot provide valid timing, do not generate a replacement itinerary. Transitous (MOTIS 2 on open GTFS/GTFS-RT data) replaced DB Transport (`v6.db.transport.rest`) in October 2026 after DB began blocking the unofficial bahn.de/DB Navigator APIs behind it; its usage policy requires published open-source code, a contact User-Agent, a visible link to https://transitous.org/sources/, no commercial use, and coordination above ~720 `/plan` requests per day.
4. **Use OSRM only for first/last-mile walk and bike durations.** Its failures may degrade to bounded cached or estimated values, which must be visibly labeled. Do not persist route geometry or instructions.
5. **Require canonical names and units at boundaries.** API timestamps are ISO 8601 strings with an offset or `Z`; buffers enter in minutes and calculations use seconds. Reject synonym fields and incomplete upstream payloads rather than letting naming drift through the UI.
6. **Respect provider terms before feature availability.** Keep attribution visible, identify outbound traffic with a descriptive User-Agent, throttle and deduplicate requests, and prefer self-hosted or contracted routing for production OSRM use.
7. **Deploy as Cloudflare Pages with Pages Functions.** Static assets are the Vite build in `dist/`, API handlers are `functions/api/`, and `wrangler.toml` is the deployment configuration. Production deployment must pass the repository checks first.
8. **The UI talks only to `/api`.** Provider calls, throttling, caching, and attribution belong to the backend; the React UI must not call Transitous, OSRM, or Photon directly.
